# Configuration

`Default.ini`, `DefUser.ini`, `DefaultXbox.ini`, `DefUserXbox.ini` and `KeyBinds.ini` started as byte-for-byte
copies of the Epic tree's `System/` files (first commit). `tools/dev/mkrun-uc2.sh` copies them over the asset
tree's when it assembles a run tree, so this folder is where our defaults live. Every change from Epic's
file is listed here with its reason; `git log -p Engine/Config` has the exact diff.

| File | Setting | Epic | Ours | Why |
|---|---|---|---|---|
| `Default.ini` | `[URL] Port` | 1000 | 7777 | 1000 is the Xbox system-link port and is privileged (below 1024) on Linux, so a server could not listen. 7777 is the Unreal Engine 2 default. |
| `Default.ini` | `[Engine.Engine] ViewportManager` | `WinDrv.WindowsClient` | `SDL2Drv.SDL2Client` | WinDrv is Win32-only and not built; SDL2Drv is the portable client (M4). Epic's value is kept as a comment line. |
| `Default.ini` | `[Engine.Engine] RenderDevice` | `D3DDrv.D3DRenderDevice` | `UC2GLDrv.UC2GLRenderDevice` | D3DDrv is Direct3D 8 and not built. UC2GLDrv is our OpenGL device (M5); `Engine.NullRenderDevice` stays available as a commented line and through `-nullrenderer`. |
| `Default.ini` | new section `[UC2GLDrv.UC2GLRenderDevice]` | (none) | the device's settings, with the values Epic's `[D3DDrv.D3DRenderDevice]` section has where the setting exists there, plus `MaxTextureUnits`, mip biases and `CheckGLErrors=False` | The device reads its settings from its own class section. |
| `Default.ini` | `[UC2GLDrv.UC2GLRenderDevice]` and `[UC2GL4ESDrv.UC2GL4ESRenderDevice]` `LevelOfAnisotropy`, `AntiAliasing` | `LevelOfAnisotropy=1` (D3DDrv section), no anti-aliasing key | `16`, `4` (also the compiled defaults) | The owner's O-8 (2026-10-06). Anisotropy as D3DDrv applied it (the default minifying filter of every stage, clamped to the hardware's maximum). Anti-aliasing: a 4x multisampled main framebuffer on desktop GL, FXAA in the present pass on OpenGL ES 2 / WebGL 1 (no multisampled framebuffers there); `-glaa=N`, `-glnoaa`. Picture comparisons and the self-test run with `-glnoaa` (`tools/dev/run-uc2-shot.sh` adds it). |
| `Default.ini` | `[UC2GLDrv.UC2GLRenderDevice] UsePixelShaders`, `PrecompileVertexShaders` | (none) | `True`, `True` | M6. `UsePixelShaders` draws pixel-shader materials with GLSL programs translated from Epic's Xbox shaders; `False` restores the M5 behaviour (every such material drawn with its first texture stage) for A/B comparison. Also `-nopixelshaders` / `-pixelshaders` on the command line and the console command `PIXELSHADERS [0\|1]`. `PrecompileVertexShaders` compiles the vertex shader of every combination in `VertexShaderConfigs.ini` at start-up (0.2 s under software GL). Both are also the compiled defaults. |
| `Default.ini` | `[Engine.Engine] AudioDevice` | `Engine.NullAudioDevice` | `UC2ALAudio.UC2ALAudioSubsystem` | M8: the OpenAL Soft device playing the cooked XACT data (`tools/cook-audio.py`). `Engine.NullAudioDevice` stays as a commented line and is still selectable; `-nosound` (the engine's own switch, `UEngine::InitAudio`) also selects it for one run. Without libopenal, without an output device or without the cooked data the game runs silent with one `Init:` line. |
| `Default.ini` | new section `[UC2ALAudio.UC2ALAudioSubsystem]` | (none) | `OutputDevice=` (empty: the default device), `Backends=` (not written: compiled default `pipewire,pulse,alsa,oss`, OpenAL Soft's own Linux order made explicit; it becomes `ALSOFT_DRIVERS` unless the environment sets that; the log names the backends tried and the one playing), `WaveFile=` (render to a .wav through OpenAL Soft's wave writer; also `-audiowave=<file>`), `MaxVoices=64`, `ZoneReverb=True`, `UseEFX=True` (also `-noefx`), `MusicFades=True`, `CueLog=True` | M8. Also the compiled defaults. `ZoneReverb` and `MusicFades` are differences from the shipped Xbox code (zone reverb was `#if 0`, fades were ignored); `False` gives the Xbox behaviour. `CueLog` writes one `DevSound` line per cue request; `DevSound` stays suppressed (Epic's `[Core.System] Suppress=DevSound`), the test scripts unsuppress it in their run tree only. Details: `docs/porting/analysis/audio.md`. |
| `Default.ini` | `[UC2GLDrv.UC2GLRenderDevice] UsePostProcess`, `DOFShippedBlurAlpha` | (none) | `True`, `True` | M7. `UsePostProcess` turns on what the Xbox build does with render targets and Epic never implemented on PC: distortion (glass, heat shimmer, energy fields), emissive glow and bloom, depth of field, the blur and colour-remap camera effects, dynamic gamma. The device then reports the `XboxPostProcess` capability and the engine's Xbox-only post-process paths run. `False` restores exactly the M6 behaviour, for A/B comparison. Also `-nopostprocess` / `-postprocess` on the command line, the console command `POSTPROCESS [0\|1]` and `-glpptoggle=<seconds>,...`. It needs `UsePixelShaders=True`. `DOFShippedBlurAlpha=True` (console: `DOFSHIPPEDALPHA [0\|1]`) makes the always-on depth of field use the blur alpha the shipped binary used (65 in every camera mode) instead of what script sets (100 in third person, 65 in first person); decided by the owner's review of 2026-10-06 (PLAN.md O-3): the ini default is `True`, the Xbox look (the Xbox was built from the same header, so it read 65 too, by inference). The compiled defaults are `True` and `False`: without an ini line the device follows script. |
| `Default.ini` | new section `[UC2GL4ESDrv.UC2GL4ESRenderDevice]` | (none) | the values of `[UC2GLDrv.UC2GLRenderDevice]` | M11. The GL4ES binding of the same driver is a subclass and reads its own section. On Linux it is the twin of the web renderer, selected with `-gl4es`; `RenderDevice` stays the desktop device. |
| `Default.ini` | `[SDL2Drv.SDL2Client] MaxDistortion` | (no such key in the PC client section; `DefaultXbox.ini` has 35.0) | `35.0` | M7. `UClient::MaxDistortion` is the largest screen-space displacement, in pixels of a 640x480 frame, a distortion material may cause; without the key it reads 0 and distortion would not displace anything. The Xbox value. (The GL device also uses 35 when it finds the value unset, so an older `Avaris.ini` keeps working.) With post-processing on the device also sets the client's `DynamicGamma` and `LuminosityBias` as `UClient::Init` does on Xbox; `DYNAMICGAMMA 0` on the console switches the dynamic gamma off. |
| `Default.ini` | `[UC2GLDrv.UC2GLRenderDevice] DistortionCullDistance` | (none: a constant, `DISTORTION_CULL_DISTANCE = 5000` in `D3DDrv/Src/D3DMaterialState.cpp` 1377) | `15000` | Owner's review of 2026-10-06, O-7 (tuning, not a fix): the distance over which screen-space distortion (glass, water, heat shimmer) fades out. `DistortionAccum.vsh` scales each vertex's distortion by `1 - saturate(z/D)^2` (z: depth in front of the camera, in Unreal units); with the Xbox's 5000 a pane 2500 units away keeps 75% of its distortion, at 4000 36%, at 5000 none, which is why the DM-Praxis panes lose it across the round room. 15000 keeps 97% at 2650 units and 89% at 5000. `5000` gives the Xbox exactly; the compiled default (no ini line) is 5000 too. Console: `DISTORTIONCULLDISTANCE [<units>]` (no argument: show). Details and pictures: `docs/porting/analysis/fx-fixes.md`, O-7. |
| (none: no file changed) | optional section `[UC2Movie]` `StartupMovies=`, `Cinematics=`, `LoadingMovie=` | (none) | not present; read with default `True` | M9: switches for the full-screen movies (`Engine/Src/UnMovie.cpp`). Not written to any ini: absent means on. Also `-NOMOVIE` (no full-screen movies) and `-NOSTARTUPMOVIES` (no logos) on the command line (UE3's switch names; UE2 had none). Details: `docs/porting/analysis/video.md`. |
| `Default.ini` | new section `[SDL2Drv.SDL2Client]` | (none) | copy of `[WinDrv.WindowsClient]` | The client reads its settings from its own class section; same values as the PC client's (640x480 windowed, gamma, detail). `MenuViewportX/Y` and `ScaleHUDX` came along with the copy; UC2's `UClient` does not read them. |
| `Default.ini` | `[SDL2Drv.SDL2Client] UIScaleMode`, `UIMenuBackground`, `UISharpText` | (none: the UI drawn 1:1 from the top-left of any window) | `Fit43`, `Fill`, `True` (also the compiled defaults) | D-2 (owner's review 2026-10-06: "make the UI to scale to the 4:3 of fullscreen and be centered"). `Fit43`: the canvas presents UC2's 640x480 design space to the menus and the HUD and draws it in the largest centred 4:3 rectangle of the window (fitted to the height, or to the width on a window narrower than 4:3); the 3D world, full-screen fades/flashes and markers on actors use the whole window; identical to before at 640x480. `Native640` gives the old behaviour back. `UIMenuBackground`: a menu page's full-screen background (`T_UI_2.XX_Background`) fills the window keeping its aspect (`Fill`) or stays in the box (`Box`); the menu level behind it is 3D and fills the window either way. `UISharpText`: when the UI is scaled up, text keeps the layout of its 640x480 font and takes its glyphs from the smallest bigger size of the same family in the font's package (`T_Fonts2.SuiGeneris_12/18/20/24/28/40pt`), so it stays crisp; `False` magnifies the small glyphs. Console `UISCALE [Native640\|Fit43] [Box\|Fill] [Sharp\|Soft]` switches for the session. `docs/porting/analysis/ui-scale.md`. |
| `Default.ini` | `[SDL2Drv.SDL2Client] UseJoystick` | (WinDrv: `False`) | `True` | M10: game pads through SDL's GameController API (`Source/SDL2Drv/Src/SDL2Pads.cpp`); WinDrv's DirectInput joystick was off by default. |
| `Default.ini` | `[SDL2Drv.SDL2Client] PadButtonThreshold`, `PadStickDeadZone`, `PadRepeatDelay`, `PadRepeatRate`, `PadRumble`, `PadRumbleScale`, `JoyDeadZone`, `LogInput` | (none) | `30`, `0`, `0.2`, `0.1`, `True`, `1`, `0.35`, `False` | M10: what the Xbox driver hard-codes, as settings with the Xbox's values (`XINPUT_GAMEPAD_MAX_CROSSTALK` 30/255; no driver dead zone, the bindings carry `DeadZone=`; repeat 0.2/0.1 s; `[XboxDrv.XboxClient] JoyDeadZone`). `LogInput` turns on the `SDL2Input` log lines. | `Default.ini` | new section `[SDL2Drv.PadMap]` | (none) | SDL control name = `Joy1`..`Joy16` / `JoyX JoyY JoyU JoyV` [`Invert`] | M10: the SDL controller -> Xbox control table (`docs/porting/analysis/controls.md` has the evidence per row; Black = right shoulder, White = left shoulder by convention). `uc2.bin` also replaces, for the current run and in the derived `Avaris.ini`, a driver the ini names that this
build does not contain (`WinDrv.WindowsClient`, `D3DDrv.D3DRenderDevice`, `XboxDrv.XboxClient`...) with
`SDL2Drv.SDL2Client` / `Engine.NullRenderDevice` / `Engine.NullAudioDevice`, and logs it, so an ini from the
PC or Xbox release still boots. `-nullrenderer` selects `Engine.NullRenderDevice` (also written to
`Avaris.ini`, like any setting changed at run time).

## `web/` - the browser build's boot inis (M4w)

`web/Default.ini` and `web/DefUser.ini` are preloaded into the web build as `/System/Default.ini` and
`/System/DefUser.ini` (`Source/SDLLaunch/cmake/Web.cmake`); `appInit` derives `Avaris.ini` and `User.ini`
from them in the browser. A host must therefore not serve the asset tree's copies of these four names.
They are GENERATED: `tools/dev/sync-web-ini.py` writes them as the two files above with the rows below and
nothing else (`--check` fails when they are not that). So a change of the native defaults reaches the browser
by running the script, not by copying sections by hand: at M11 the web copies were still the M4w ones, without
M7's `MaxDistortion` and without M10's key table, pad map and bindings (the menus would not have answered the
keyboard). A new web-only difference is a new entry in the script's `DELTAS` (a fixed value) or `WEB_KEYS` / `WEB_SECTIONS`
(whatever the web file has is kept) and a row here:

| File | Setting | `Engine/Config` value | Web value | Why |
|---|---|---|---|---|
| `Default.ini` | `[Engine.Engine] AudioDevice` | `UC2ALAudio.UC2ALAudioSubsystem` | `UC2ALAudio.UC2ALAudioSubsystem` (was `Engine.NullAudioDevice`) | M11/O-2: the same device as native, on openal-soft's Web Audio backend linked into the module (AudioWorklet; the context starts on the page's first click or key). `Engine.NullAudioDevice` stays as a commented line. Without Web Audio, AudioWorklet or cross-origin isolation the device logs why and the game runs silent. |
| `Default.ini` | new section `[UC2ALAudio.UC2ALAudioSubsystem]` | compiled defaults (section in `Engine/Config/Default.ini`) | the native values; `Backends=` empty (the web build has one backend, `web`) | M11/O-2: written out so the web set is complete and readable. |
| `Default.ini` | new section `[UC2Movie]` | absent (= all on) | `StartupMovies=True`, `Cinematics=True`, `LoadingMovie=True` | M11/O-2: movies on, written out. The cooked movies must be in the web build's file manifest (`docs/porting/analysis/web-audio.md`). |
| `web/Default.ini` | `[Engine.Engine] RenderDevice` | `UC2GLDrv.UC2GLRenderDevice` | `UC2GL4ESDrv.UC2GL4ESRenderDevice` | M11: the same driver behind GL4ES on WebGL 1; its section `[UC2GL4ESDrv.UC2GL4ESRenderDevice]` is in both files. |
| `web/Default.ini` | `[Engine.Engine] AudioDevice` | `UC2ALAudio.UC2ALAudioSubsystem` | kept as the web file has it | Web-owned (`WEB_KEYS`): the web audio work sets it (openal-soft's Web Audio backend); on a branch without that work it is `Engine.NullAudioDevice`. |
| `web/Default.ini` | sections `[UC2ALAudio.UC2ALAudioSubsystem]`, `[UC2Movie]` | the native section, or none | kept as the web file has them | Web-owned (`WEB_SECTIONS`): the web audio and movie set-up (e.g. the web-only `Backends=` key). |
| `web/Default.ini` | `[SDL2Drv.SDL2Client] UseJoystick` | `True` | `False` | Game pads through the browser's Gamepad API are untested. |
