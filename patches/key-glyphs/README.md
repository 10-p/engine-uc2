# key-glyphs

GUI + UCMenu (H-5): player one's keys in place of the pad's button glyphs while they use the keyboard or the mouse.
The work is the engine's (`Source/Engine/Src/UnKeyGlyphs.cpp`: which key, when, the drawing); this set switches it on
and marks what it cannot know by itself:

- `new/GUI/Classes/KeyGlyphs.uc` (our own text): the engine shows keys only when the class `GUI.KeyGlyphs` exists, so
  a shipped GUI.u keeps the Xbox glyphs. `KeyGlyphs.InGame(S)` marks the button glyphs of a text as the GAME's buttons
  (the glyph character gets the high bit; the engine gives the button font the same glyph there).
- `UCMenu.diff`, `PlayerComboPanel.Update` (1 line): the character pages' combo instructions ("X, l" = combo button,
  then the left trigger) are game buttons inside a menu: marked with `InGame`, so they show the keys that do it in the
  game (X, then the right mouse button) and not the menus' keys for those pad buttons (X, PageUp).

- **Ini keys**: `[GUI.KeyGlyphs] ShowKeys` (system ini, read by the engine; False: always the Xbox glyphs).
- **Depends on**: epic-fixes (it rebuilds GUI and UCMenu). Comes before keys-menu in `sets.txt` because
  `uc-patches.py make` cannot yet make a set for a package to which an earlier set added classes (keys-menu's UCMenu
  classes have no identity line).
- Generated by `tools/dev/uc-patches-regen.sh`. Notebook: `docs/porting/analysis/h5-key-glyphs.md`.
